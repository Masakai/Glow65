# 6502 ワンボードマイコン エミュレータ 設計書(Swift)

作成日: 2026-10-11 / ステータス: 草案(実装前)

## 1. 目的と方針

- 自作仕様の6502ワンボードマイコン(以下「本ボード」)を Swift でエミュレートする。
- ソフトは Microsoft BASIC for 6502 v1.1(MIT)と自作モニタROMを載せる。
- 実在機のROMを使わないため、ROMの著作権問題は発生しない。
- Apple II の実機ROMは扱わない。将来の拡張候補とし、同梱もしない。
- Altair 8800 / IMSAI 8080 風のフロントパネルを持つ。LED でCPUの動き(アドレス、データ、状態)を見られることを主目的とする。
- スイッチは制御系(電源、リセット、実行/停止、ステップ、速度)のみ。アドレス/データ設定スイッチ(EXAMINE/DEPOSIT)は持たない。

## 2. 調査で確認した前提

| 項目 | 確認結果 | 出典 |
|---|---|---|
| ライセンス | MIT(`LICENSE` 先頭で確認) | github.com/microsoft/BASIC-M6502 |
| 構成 | `m6502.asm` 1ファイル、約6,950行。2025-09-05 にアーカイブ済み(読み取り専用) | 同上 |
| 機種切替 | `REALIO` の値で条件コンパイル(0=PDP-10シミュレーション、1=KIM-1、2=OSI、3=PET、4=Apple II、5=STM) | `m6502.asm` 冒頭 |
| 構文 | MACRO-10 系(`TITLE`、`SEARCH`、`IFE`/`IFN`、`^O` 8進表記)。ca65 などの現代アセンブラでは**そのままビルドできない** | `m6502.asm` を直接確認 |
| 入出力 | 機種ごとに `OUTCH`、`CQINCH`、`ISCNTC` などを固定アドレス(8進)で定義し、その機種のモニタROMを呼ぶ | `m6502.asm` 53-102行付近 |

## 3. 最大のリスク: BASICのビルド

`m6502.asm` を本ボード用ROMにする工程が未検証である。実装の最初にスパイクとして検証する。

- 案A: 小さな変換スクリプトで MACRO-10 構文を ca65 構文へ変換する(`IFE`/`IFN` → `.if`、`^O` → `$`、`==` → `=` など)。
- 案B: Swift 製の簡易アセンブラで、必要な疑似命令だけを自作して直接ビルドする。
- 案C: 既存のコミュニティ移植を調べる(ただしライセンスは別途確認が必要)。

判断基準は、変換後のROMが本ボード上で `OK` プロンプトまで到達すること。案Aを第一候補とする。

## 4. ボード仕様(案)

| アドレス | 内容 |
|---|---|
| `$0000-$7FFF` | RAM 32KB |
| `$A000-$A001` | UART(MC6850 風のサブセット。`$A000` 状態/制御、`$A001` データ) |
| `$F000-$FFFF` | ROM 4KB(モニタ + 入出力ジャンプテーブル。リセット/IRQ/NMIベクタを含む)※当初案の `$E000` から変更 |
| `$C000-$EFFF` | ROM 12KB(Microsoft BASIC。実測 約8.6KB。8KB に収まらなかったため 12KB に拡張) ※当初案の `$C000-$DFFF` から変更 |

- BASICの `REALIO` に本ボード用の枠(値 6)を追加し、`OUTCH`、`CQINCH`、`ISCNTC` を自作モニタのジャンプテーブルへ向ける。
- UART状態ビット: bit0 = 受信データあり(RDRF)、bit1 = 送信可(TDRE)。
- 割り込みは第1段階では未使用(`IRQ`/`NMI` はベクタのみ用意)。
- S-100バスの再現は範囲外。将来、拡張スロットの抽象化として検討する。
- 上記アドレスは草案であり、BASICの `RAMLOC`、`ROMLOC`、`STKEND` 等の制約を実測してから確定する。

### 5.1 Core6502

- `protocol Bus { func read(_ addr: UInt16) -> UInt8; func write(_ addr: UInt16, _ value: UInt8) }`
- `struct CPU6502`: レジスタ(A、X、Y、SP、PC、P)と `mutating func step(bus:) -> Int`(消費サイクルを返す)。
- 第1段階は NMOS 6502 の公式命令に限定し、10進モード(BCD)も実装する。非公式命令と 65C02 は後回しとする。
- 速度重視で、`step` はジェネリクスで `Bus` を特殊化できる形にする。

### 5.2 Glow65

- `final class SBCBus: Bus`: RAM配列、ROM配列、デバイスのアドレス範囲表。
- `UART`: 送信バッファと受信FIFOを持つ。ホスト側は `send(byte:)` と `onTransmit` で接続する。
- 1MHz 相当のペースで実行する(サイクル数 × 時刻でスロットル)。

### 5.3 glow65-cli

- 標準入出力を raw モードにして UART へ接続する。
- Ctrl-C は BASIC の `ISCNTC` 用に UART へ渡す。エミュレータ自体の終了は別キー(例: Ctrl-\)にする。
- オプション: `--rom <path>`、`--trace`、`--speed <MHz>`。

### 5.4 Glow65App(GUI。主要な実行形態)

SwiftUI の macOS アプリ。1ウインドウに、フロントパネルと端末ビュー(UARTに接続)を並べる。
CLI はテスト、自動化、ヘッドレス実行用に残す。

### 5.5 フロントパネル

**LED**

| 群 | 内容 |
|---|---|
| アドレス | A15-A0 の16個 |
| データ | D7-D0 の8個 |
| バス状態 | R/W、SYNC(命令フェッチ) |
| CPU状態 | RUN、HALT(停止中)、IRQ、NMI、RESET |
| 周辺 | UART の送信/受信 |
| レジスタ(任意表示) | A、X、Y、SP、PC、フラグ N V - B D I Z C |

**スイッチ(制御系のみ)**

| スイッチ | 動作 |
|---|---|
| POWER | 電源。OFF で全LED消灯、ON でリセットから開始 |
| RESET | リセット信号 |
| RUN / STOP | CPUの実行と停止 |
| STEP | 停止中に1命令進める。長押しで連続 |
| SPEED | 1Hz、10Hz、100Hz、1kHz、100kHz、1MHz(フル) |

**実現方法**

- コア側に `PanelState`(最後に見えたアドレス、データ、R/W、SYNC、レジスタ)を公開する。
- 1MHz ではLEDが人間の目に追えないため、実機のパネルと同様に**残光(平均輝度)**で表示する。バスアクセスごとに各ビットの点灯回数を積算し、表示フレーム(60Hz)ごとに明るさへ換算して積算値をリセットする。低速時は積算がそのまま現在値になる。
- 積算は `Bus` をラップする計測用バスで行い、パネル非接続時(CLI等)は外してオーバーヘッドをなくす。
- 命令単位の STEP でも、その命令で発生したバスアクセス列(アドレス、データ、R/W)を記録しておけば、**サイクル単位の表示**として1アクセスずつ再生できる。ダミーリード(インデックス補正時など)は第1段階では再現しない(制限事項)。
- 見た目は、スライドスイッチ、ラベルは自作の意匠にする。Altair/IMSAI の実物の写真やロゴは使わない。

## 10. フェーズ0で判明した事項(2026-10-11)

`m6502.asm` の構文を集計した結果、変換の対象は次のとおり。

- 条件コンパイル: `IFE`/`IFN` が約300箇所、`IFNDEF` あり。`<` `>` で複数行を囲む。
- マクロ: `DEFINE` が31個(`LDWD`、`STWD`、`PSHWD`、`JEQ`、`SYNCHK`、`INCW` など)。
- 独自ニーモニック: `LDAI`、`CMPI`、`LDADY`、`STADY` など。即値、`(zp),Y` 形式を名前で区別する。
- 疑似命令: `REPEAT`、`IRPC`、`XWD`(`BIT` 命令を使った飛ばし技の埋め込み)、`PURGE`、`^O`(8進)など。

単純な文字列置換では済まず、条件ブロックの対応付けとマクロの再定義が必要。

追加で判明した点(2026-10-11、`m6502.asm` を直接確認)。

- `SEARCH M6502` のマクロライブラリはリポジトリに含まれない。`ADR(x)`(2バイトのアドレス)、`LDAI`/`CMPI`(即値)、`LDADY`/`STADY`/`CMPDY`(`(zp),Y`)、`JMPD`(`JMP (x)`)などの意味は、使われ方から再定義する必要がある。
- 数値だけの行(`0`、`44`、`LINLEN`)はデータバイト、`BLOCK n` は領域確保として扱われる。
- 数学パッケージ部分(4847-6671行)は `RADIX 8`。接頭辞なしの数値が8進になる。
- `ORG 0`(ゼロページ側)、`ORG 255`(ページ1側)、`ORG ROMLOC`(ROM側)の3領域に分かれ、ROM版ではゼロページの初期値をROMから RAM へ複写する。この配置の扱いは未解析。
- `XWD ^O1000,^O044` などは36ビット語の記法。`BIT` 命令の1バイト目(`$24`/`$2C`)に読み替える。
- `<` `>` が式の括弧とブロック区切りを兼ね、入れ子になる。
- 参考: `mist64/msbasic`(cc65移植)は README に 2-clause BSD とあるが、LICENSE ファイルは見当たらない。Microsoft の MIT 公開(v1.1)とは別系統の復元物であり、権利関係が不明確なため、**ソースとしては使わない**。比較用の参照ビルドに使う場合も、ローカルのみで再配布しない。

結論: フェーズ0は当初想定より大きい。CPUコア(フェーズ1)とは独立しているため、CPU、ボード、フロントパネルを先に進め、BASIC変換は並行トラックとする案を推奨する。

## 12. BASIC変換の結果(2026-10-12)

`Tools/build_basic.sh` で、Microsoft の `m6502.asm`(MACRO-10 構文)を ca65 用に変換してビルドし、`ROM/basic/build/basic.bin`(12KB、うちコード 8,632 バイト)を生成する。本ボード上で起動し、`PRINT`、`FOR/NEXT`、文字列関数、`SQR`/`SIN`、`PEEK`/`POKE`、エラー表示が動作することを統合テスト(`BasicTests`、5件)で確認した。起動時の空き領域は 31,743 バイト。

### 構成

| ファイル | 役割 |
|---|---|
| `ROM/basic/upstream/m6502.asm`、`LICENSE` | Microsoft の原典と MIT ライセンス文(変更しない) |
| `Tools/convert_m6502.py` | MACRO-10 → ca65 変換器(標準ライブラリのみの Python) |
| `ROM/basic/prelude.inc` | 原典が `SEARCH M6502` で読むライブラリ相当のマクロ(`LDAI`、`LDADY`、`JMPD`、`DC` など) |
| `ROM/basic/board.inc` | 本ボード固有の定数(`CZGETL`) |
| `ROM/basic/basic.cfg` | ld65 のメモリ配置(ゼロページ/ページ1は RAM、`$C000-$EFFF` が ROM) |
| `ROM/basic/build/` | 生成物(`m6502.s`、`.lst`、`.map`、`basic.bin`)。`.gitignore` 対象 |

### 構成の選択

原典の `REALIO=2`(OSI)を基にした。理由は、OSI 構成が MC6850 系 ACIA(状態: bit0=受信可)を前提にしており、本ボードの UART と同じ作りであること、トリゴノメトリ関数(SIN/COS/TAN/ATN)を含むこと。KIM 構成は ROM 節約のため三角関数を持たない。

### 原典への差し替え(`convert_m6502.py` の `PATCHES`)

| 原典 | 差し替え後 | 理由 |
|---|---|---|
| `REALIO=4` | `REALIO=2` | OSI 構成を使う |
| `LNGERR==0` | `LNGERR==1` | 長いエラーメッセージ(ROM に余裕あり) |
| `ROMLOC= ^O20000` | `49152`($C000) | BASIC ROM の位置 |
| `RAMLOC==^O100000` | `1024`($0400) | BASIC プログラム領域の開始(`$0200-$03FF` はモニタ用に残す) |
| `OUTCH==^O177013` | `61443`($F003) | モニタの `CHROUT` |
| `LDA ^O176000`/`^O176001` | `$A000`/`$A001` | UART の状態/データ |

### 変換で対処した原典の癖

- シンボルは先頭6文字だけが有効(例: `RESTORE` と `RESTOR` が同一)。全シンボルを6文字に切り詰めた。
- `RADIX 8` の区間では、`8` や `9` を含む数だけ10進として扱う(`8*ADDPRC+230`)。
- `<` `>` が式の括弧とブロック区切りを兼ねるため、文字単位の構文解析で対応付けた。
- `LABEL: IFE ...,<` のようにラベルとブロックが同じ行にある。
- `BIT` 命令による飛ばし(`XWD ^O1000,^O044`)は、オペコード1バイト(`$24`/`$2C`)に変換した。
- `.set` は数値だけのシンボル、`=` は番地を含むシンボルに使い分けた。
- ゼロページ領域(`ORG 0`)は絶対アドレス(`.org $0000`)で配置し、`CHRGET` など自己書き換えコードがゼロページ命令になることを確認した(`INC CHRGET+7` が `E6 CA`)。
- マクロの仮引数 `A`/`X`/`Y` はレジスタ名と衝突するため別名にした。

### 本ボードへの影響

- モニタを `$F000` に移し、ジャンプテーブルを `CHRIN`/`CHROUT`/`ISCNTC`/`MONITOR`/`GETKEY` の5本にした。`CHROUT` は最上位ビットを落とす(BASIC の短いエラー表示が7ビット端末向けのため)。
- モニタの `B` コマンドは `$C000` の `JMP INIT` に入る。BASIC は起動時に「MEMORY SIZE?」と「TERMINAL WIDTH?」を尋ねる(Enter で既定値)。
- 起動バナーの機種名は「GLOW65 BASIC  (MICROSOFT BASIC V1.1 FOR 6502)」に差し替えた(`PATCHES`)。続く「COPYRIGHT 1978 MICROSOFT」は原典のまま残す。

### 未確認

- 原典のバイナリとの突き合わせ(原典に対応するバイナリがないため)。検証は動作テストで行った。
- `GET`、`WAIT`、`USR`、配列、文字列の大量操作、`ON GOTO` などの網羅的な確認。
- 長時間実行(ガベージコレクション)の安定性。

## 14. 自作プログラムを動かす手順(2026-10-12)

学習用として「自分で書いたプログラムを動かす」流れを用意した。

- `ROM/user.cfg`、`Tools/assemble.sh`: ca65 の構文で書いたプログラムを、`$0300-$03FF` に置く生のバイナリにする。
- `Glow65`: `ProgramImage`(`ファイル@16進アドレス` の読み取り)、`SBCBus.loadRAM`(RAM の範囲を検査)、`MachineRunner.loadProgram`(電源が入っているときだけ受け付ける)。
- `glow65-cli --load ファイル@アドレス`、`Glow65App --load ファイル@アドレス`(電源を入れるたびに RAM へ読み込む)、アプリの **File → Load Program…**(⌘O、読み込み先アドレスを指定できる)。
- `tutorial/`: 手順書(英語、日本語)と、サンプル `counter.s`、`counter.bin`(11 バイト)。LED カウンタを題材に、手入力(`E`)、ファイルの読み込み、`G` での実行、遅くして1アクセスずつ観察、練習問題3つを説明する。
- メモリの使い分け: `$0200-$027F` はモニタの行入力バッファ(ここにプログラムを置くと、起動のために打つコマンドで上書きされる)、`$0300-$03FF` が自作プログラム用、`$0400` 以降が BASIC。
- 手順書の内容は `TutorialTests`(11 件)で確認している。手順書のバイト列、最初の1周のバスアクセス12回の表、練習問題の結果が対象。
- 未確認: **File → Load Program…** のファイル選択パネルは、開いて表示を確認したが、実際にファイルを選んで読み込む操作は試していない(読み込みの処理そのものは `--load` とテストで確認済み)。

## 15. モニタの逆アセンブル(`L` コマンド)(2026-10-12)

- コマンド: `L aaaa [bbbb]`。終了アドレスを省くと 16 命令、指定するとそのアドレスまで。`$FFFF` を越えたところで止まる。
- 表示: `AAAA  BB BB BB  MNEMON OPERAND`。例: `0302  8D F0 03  STA   $03F0`。分岐命令は、分岐先のアドレスを表示する。未定義のオペコードは `.BYTE $xx`(1 バイト)。
- 実装: `ROM/monitor.s`(約 1.2KB 増。使用量は 663 バイトから約 1.8KB)。表は `Tools/gen_disasm_tables.py` が `Sources/Core6502/OpcodeTable.swift` から生成する(`ROM/disasm_tables.inc`)ので、CPU コアの命令表と食い違わない。
- オペランドは命令の長さの分だけ読む。UART のデータレジスタ(`$A001`)のように、読むと状態が変わる場所を、余分に読まないため。
- ゼロページの `$FA-$FF` を作業領域に使う(モニタは `$F0-$FF` を使う)。
- テスト(`DisassemblerTests`): 全 256 オペコード × 3 通りのオペランド(正のオフセット、負のオフセット、ゼロ)について、`L` の出力が CPU コアの命令表から作った基準の書式と一致することを確認。チュートリアルの一覧、練習問題の一覧、既定の 16 命令、アドレス空間の終端、ヘルプの表示も確認。
- 作業中に見つけた不具合: 終了アドレスの解析(`PARSEHEX`)が、命令数の保存先 `TMP` を上書きしていた。テスト(既定 16 命令)で発見し、解析のあとに設定するよう修正した。
- アプリのパネルに「実行中の命令」を出す機能は作っていない(モニタのみ)。
