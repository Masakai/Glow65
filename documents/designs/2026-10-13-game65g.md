# GAME65G(GAME 言語インタプリタ)設計書

2026-10-13 作成。同日、§4.2 の独自の決定と §8 の影響範囲の承認を得て実装した(結果は §11)。

## 1. 目的

Glow65 に、Microsoft BASIC と並ぶ2本目の言語として、GAME 言語のインタプリタ **GAME65G** を自作して載せる。

- GAME は大西博氏が 1978 年に月刊アスキーで発表した、記号で書く Tiny BASIC 系の言語。
- 1979 年に鈴木仁志氏が PET 向けに移植した **GAME65** があるが、そのコードは使わない(著作権の理由。§2)。
- 名称の GAME65G は、GAME65 と別物であることを NOTICE.md とバナーで明示する。

## 2. 仕様の出典と、書き起こしの方針

言語仕様は著作権の保護対象外(著作権法 10 条 3 項「プログラム言語、規約及び解法」)。コードは一から書く。

使う出典は次の2つだけ。

| 記号 | 出典 | 使う部分 |
|---|---|---|
| [表1] | 月刊アスキー 特集「GAME65 & GAME-MZ」の記事「超CPU-GAMEとは?」の表1「GAME インストラクションセット」と本文 | 文法、命令、特殊レジスタ、配列、EOF マーク |
| [65] | 同特集の GAME65 の記事 | 追加の二項演算子 `&` `.` `!`、`$` が待たないこと、`%` の書き方 |

守ること。

- GAME65 の内部構成(番地、ゼロページの割り当て、ダンプリスト)は参照しない。本書の番地は Glow65 に合わせて独自に決めた。
- ほかの GAME 処理系のソースコードは読まない。
- テスト用の GAME プログラムは自作する。記事のプログラムは使わない。
- 出典の PDF はリポジトリに入れない。

| 項目 | 決定 |

## 4. 言語仕様

### 4.1 出典にある仕様

- 行番号は 1〜32767。行番号のあとに空白がなければ、その行は注釈になる([表1] REM)。
- 文は空白で区切る。1行に複数の文を書ける。
- 定数は 10 進と `$` 付きの 16 進。値はすべて 16 ビット。
- 変数は `A`〜`Z` の 26 個。2文字目以降の英字は無視する(`ALPHA` は `A`)。
- 演算子に優先順位はなく、左から計算する。カッコは優先される。
- 配列: `V(n)` は 2 バイト、`V:n)` は 1 バイト。`V` の値を基準アドレスにする。2 バイトは下位・上位の順([65])。
- 特殊レジスタ: `=` プログラム先頭、`&` プログラム末尾、`*` RAM 末尾、`'` 乱数。

| 機能 | 書き方 | 出典 |
|---|---|---|
| LIST | `0`(全部)、`n/`(n 行から) | [表1] |
| RUN | `#=1`(先頭から)、`#=n`(n 行から。なければ n より大きい最初の行) | [表1] |
| NEW | `&=0`(末尾ポインタを先頭にし、EOF マーク `$FF` を書く) | [表1] |
| OPEN / LOCK | `&:0)=$FF` / `&:0)=$F0`(LOCK 中は行の追加・削除を受け付けない) | [表1] |
| SEARCH END | `==` | [表1] |
| プログラム切り替え | `=n` | [表1] |
| RAM 末尾 | `*=n` | [表1] |
| 10 進出力 | `?=n`、`?(m)=n`(m 桁右詰め、1≦m≦255) | [表1] |
| 16 進出力 | `??=n`(4 桁)、`?$=n`(2 桁) | [表1] |
| 1文字出力 | `$=n` | [表1] |
| 空白 | `.=n`(0≦n≦255) | [表1] |
| 改行 | `/` | [表1] |
| 文字列 | `"文字"` | [表1] |
| 数値入力 | `V=?`(1行を式として評価) | [表1] |
| 1文字入力 | `V=$`(待たない。なければ 0) | [65] |
| 代入 | `V=n`、`V(i)=n`、`V:i)=n` | [表1] |
| IF | `;=n`(0 なら次の行へ) | [表1] |
| GOTO | `#=n`(n=0 なら何もしない) | [表1] |
| END | `#=-1` | [表1] |
| GOSUB / RETURN | `!=n` / `]` | [表1] |
| CALL | `>=n`(機械語を JSR で呼ぶ) | [表1] |
| FOR | `V=a,b` | [表1] |
| NEXT | `@=V+1` など(`=` の次が変数名) | [表1] |
| DO / UNTIL | `@` / `@=(条件)` | [表1] |
| 乱数 | `'=n`(種)、`V='n`(1〜n) | [表1] |
| 剰余 | `%項`(直前の割り算の余り。例 `%(A/B)`) | [表1][65] |
| AND / OR / XOR | `&` / `.` / `!`(二項演算子) | [65] |

NEXT と UNTIL は同じ仕組みとして実装する([表1] の説明による)。`@=式` は、`=` の次が変数名ならその変数に値を入れる。値が第2スタックの終値より大きければループを抜け、そうでなければループの先頭へ戻る。DO は終値 0 を積む。

### 4.2 出典にない部分の独自の決定(2026-10-13 承認)

[表1] には「拡張機能は省略」と注記があり、比較演算子の一覧、エラー時の動作などは書かれていない。次のように決める。

| # | 項目 | 案 | 理由 |
|---|---|---|---|
| D1 | 比較演算子 | `=` `<>` `<` `>` `<=` `>=`。真は 1、偽は 0 | [表1] に `;=A<>B` の例だけがある |
| D2 | 比較と FOR の符号 | 符号付き 16 ビット | `I=-5,5` のようなループを書けるようにする。RAM の番地(`$0000-$7FFF`)は正の数に収まる |
| D3 | `V(i)` の番地 | `V+i*2` | 2 バイトの要素の配列として使えるようにする([表1] 本文の配列の例と合う) |
| D4 | 0 で割る | エラー | |
| D5 | エラー表示 | `ERR` と行番号を出してプロンプトへ戻る(直接実行なら `ERR` だけ) | ROM の容量を節約する |
| D6 | 中断 | 文の間で Ctrl-C を調べ、`BRK` と行番号を出す。Ctrl-C 以外のキーは1文字だけ保持し、`$` で読めるようにする | モニタの `ISCNTC` はキーを捨てるため使わず、`GETKEY` で読む |
| D7 | 小文字 | 文字列と注釈の外は大文字にする | BASIC の小文字入力(設計書 §25)と揃える |
| D8 | 行の削除 | 行番号だけを入力すると、その行を削除する | [表1] に削除の方法がない |
| D9 | LOAD / SAVE | 作らない | Glow65 にテープがない |
| D10 | INPUT STR | 作らない | [表1] に書式がない |
| D11 | プロンプト | `>` | モニタの `*` と区別する |
| D12 | 起動コマンド | モニタの `T`(コールドスタート。プログラムを消す)。ウォームスタートは `G 8003` | `B` と同じ1文字。Tiny 系の言語であることから |
| D13 | モニタへ戻る | `>=$F009`(モニタのウォームスタート) | 専用の命令を足さない |
| D14 | バナー | `GAME65G` と版、`BASED ON GAME LANGUAGE (ASCII 1978)` | 言語の設計者は NOTICE.md に漢字で書く(ローマ字表記を確認できていないため) |

## 5. メモリの使い方

| 範囲 | 用途 |
|---|---|
| `$0000-$002C` | GAME65G の作業領域(`$F0-$FF` はモニタ用に空ける) |
| `$0080-$00B3` | 変数 A-Z(下位・上位の順) |
| `$0100-$01FF` | 6502 のスタック |
| `$0200-$027F` | モニタの行入力バッファ(使わない) |
| `$0300-$03F7` | 使わない(`>=$300` で自作の機械語を呼べるようにする) |
| `$03F8-$03FB` | 割り込みの RAM ベクタ(触らない) |
| `$0400-$047F` | GAME65G の行入力バッファ |
| `$0480-$04FF` | 数値入力 `?` のバッファ(直接実行の行を上書きしないよう分けた) |
| `$0500-$05BF` | 第2スタック(GOSUB、FOR、DO。1段 6 バイト、31 段) |
| `$05C0-$05FF` | 先打ちのキーの環状バッファ(64 バイト。§12) |
| `$0600-$7FFF` | プログラム(`=` の初期値 `$0600`、`*` の初期値 `$7FFF`) |
| `$8000-$9FFF` | GAME65G の ROM(新設) |

- ROM の先頭: `$8000` コールドスタート、`$8003` ウォームスタート。
- 命令は NMOS 6502 の範囲だけを使う(65C02 モードでも動く)。

## 6. ボードとビルドの変更

- `SBCBus`、`MemoryMap`: `$8000-$9FFF` を ROM として読めるようにする。書き込みは無視。未接続の範囲は `$A100-$BFFF` だけになる。
- `ROM/game65g/`: `game65g.s`、`game65g.cfg`(MEMORY を `$8000` から `$2000` バイトにし、溢れたらリンクエラーにする)。
- `Tools/build_game65g.sh`: `ROM/game65g.bin` を作る。
- `game65g.bin` はモニタと同じくコミットし、CI で作り直して一致を確認する(自作なので BASIC と違い同梱に制約がない)。
- `glow65-cli`、`PanelModel`: 既定で `$8000` に読み込む。`--rom` の範囲検査を `$8000` 以上に広げる。
- `Tools/build_app.sh`: アプリに同梱する。
- モニタ: `T` コマンドとヘルプの1行を足す。`monitor.bin` を作り直す。

## 11. 実装の結果(2026-10-13)

### 大きさ

- コード 2,592 バイト、データ 142 バイト(`$8000-$8AAD`)。8KB の ROM のうち約 2.7KB(§12 の修正後)。

### プログラムの形

- 1 行は、行番号(上位、下位)、行の長さ(この 3 バイトと CR を含む)、本文、CR。行番号を上位から置くので、先頭のバイトが `$80` 以上なら EOF マーク(`$FF` か `$F0`)と判別できる。
- 実行は、行頭の本文が空白でなければ注釈として飛ばす。

### 実装の要点

- 文の振り分けは、記号の表(`StmtChr`)に一致すればその処理へ、一致しなければ代入とする。
- 式は `TERM` と二項演算の繰り返し。左辺はハードウェアのスタックに積み、カッコは `EXPR` を再帰で呼ぶ。
- NEXT と UNTIL は共通の処理で、第2スタックの終値より大きければ抜ける。DO は終値 0 を積む。
- 中断の確認は、文の前ごとに `GETKEY` を読む。Ctrl-C 以外のキーは先打ちのバッファ(§12)にためて、`$` と行入力で先に返す。
- 乱数は xorshift 16 ビット(7、9、8)。`'n` は剰余に 1 を足す。割り算の余り(`%`)を上書きしないよう、符号なし除算の余りは別の場所(`WREM`)に置く。
- `.byte $2C`(BIT abs)と `.byte $24`(BIT zp)で次の命令を飛ばす書き方を、3 か所で使っている(`ERROR`/`BREAK`、`FALSE`/`TRUE`、`ARRW`/`ARRB`)。

### モニタの `T`

- `T` の判定(`CMD_T`)は `DEFISR` の後ろに置き、`?` の分岐(`jne`)の飛び先を変えるだけにした。マニュアルの第3章と第6章が番地を載せている `RESET`(`$F12A`)と `NMI_ISR`(`$F41E`)、`IRQ_ISR`(`$F421`)を動かさないため。ヘルプの文字列などの RODATA は後ろにずれた。

### テスト

- `Tests/Glow65Tests/Game65GTests.swift`(41 件。§12 の 2 件を含む)。§4 の命令、独自の決定(D1-D8、D12、D13)、`GAME65G.md` の例、バス(`$8000` が読めて書き込みが無視される)、BASIC の RAM 自動検出が `$8000` の ROM で変わらないこと。多くは NMOS 6502 と 65C02 の両方で回す。
- CLI(`glow65-cli`)とアプリ(`Glow65App --power-on --no-splash --input ...`、画面を `screencapture -l` で撮影)で、`T` で起動してプログラムを入力・実行できることを確かめた。`Tools/build_app.sh` で作るアプリの同梱は試していない。

### 文書

- マニュアル(日英)の第1、2、7、8.2 章、メモリマップの図。`$8000` を「未接続」の例にしていた実行例と第7章の問1は、`$B000` に変えた。`D B000 B00F` の出力は CLI で確かめた。
- README(日英)、NOTICE.md。

### 未確認

- 月刊アスキーの号: 特集の号が 1979 年 10 月号であることは、はせりん氏の掲載記事一覧による(二次資料)。手元の PDF には号の表記がない。

## 12. 先打ちのキーの修正(2026-10-13)

- 不具合: 当初は、中断の確認で読んだキーを 1 文字(`PENDKEY`)しか残せず、2 文字目以降を捨てていた。アプリで `0`(LIST)と `#=1` を続けて貼り付けると、LIST の間に `=1` と CR が捨てられ、`#` だけの行になって `ERR` が出た。アプリの画面で確かめた。
- 修正: 64 バイトの環状バッファ `KBUF`(`$05C0-$05FF`)と、読み出し位置 `KHEAD`(`$13`)、書き込み位置 `KTAIL`(`$2C`)にした。満杯のときは新しいキーを捨てる。Ctrl-C で中断したときはバッファを空にし、エラーでは空にしない。
- 影響: 第2スタックは `$0500-$05BF`(31 段)に縮めた。プログラムの先頭(`$0600`)は変えていない。
- テスト: LIST と実行の間に先打ちした行が欠けないこと、先打ちの後ろの Ctrl-C が効くこと。修正後、アプリで同じ貼り付けが通ることを画面で確かめた。
