# チュートリアル 6: 割り込み

[English](06-interrupts.md) | [日本語](06-interrupts.ja.md) &nbsp;·&nbsp; [← 5. USR](05-usr.ja.md)

ここまでのプログラムは、自分から確かめにいっていました。UART の状態をループで読み続け、キーが来るのを待っていました。**割り込み**は、この関係を逆にします。ハードウェアが信号を出すと、CPU は実行中の作業を中断して短いルーチン(**ハンドラ**)を実行し、そのあと元の場所にぴったり戻ります。この章では、6502 の2本の割り込み線 **NMI** と **IRQ** を使い、CPU がハンドラに入って出る様子をパネルで観察します。以下の内容はすべて Glow65 で実行し、`Tests/Glow65Tests/TutorialInterruptTests.swift` で確認しています。

## 1. 割り込みで CPU がすること

CPU は、命令を1つ実行する前に、2つの入力を調べます。

| 入力 | 出すもの | プログラムで止められるか |
|---|---|---|
| **NMI**(マスク不可) | パネルの **NMI** ボタン | 止められません。I フラグが立っていても受け付けます。1回押すと1回だけ(エッジで)起きます |
| **IRQ** | UART(受信文字があり、割り込みを許可しているとき) | 止められます。**I** フラグが 1 の間は無視します。`sei` で I を立て、`cli` で下ろします。IRQ は**レベル**で働きます。線が上がっている間、CPU は何度でも戻ってきます |

割り込みを受け付けると、CPU は次のことをします。

1. **PC** の上位バイト、PC の下位バイト、**P** レジスタの順に、スタックに積みます(`$01xx` への3回の書き込み)。
2. **I** フラグを立てます。ハンドラが、IRQ でさらに中断されないようにするためです。
3. ベクタからハンドラのアドレスを読みます。NMI は `$FFFA/$FFFB`、IRQ は `$FFFE/$FFFF` です。
4. そこへジャンプします。

ハンドラは `rti` で終わります。`rti` は P、続いて PC を取り出すので、プログラムはフラグも含めて元の状態で再開します。`rts` と違って、`rti` はアドレスに 1 を足しません。積まれた PC が、すでに次の命令を指しているからです。

CPU が保存するのは PC と P だけです。ハンドラで A、X、Y を使うなら、自分で保存して戻します(`pha` ... `pla`)。そうしないと、主プログラムのレジスタが壊れます。

## 2. このボードのベクタ

`$FFFA` と `$FFFE` のベクタは ROM にあり、書き換えられません。そこでモニタは、2つの小さなジャンプ命令を置き、RAM にある2つのアドレスを経由して飛ぶようにしています。

| RAM のアドレス | 内容 | 用途 |
|---|---|---|
| `$03F8/$03F9` | NMI ハンドラのアドレス(下位、上位) | NMI |
| `$03FA/$03FB` | IRQ ハンドラのアドレス(下位、上位) | IRQ と `BRK` |

リセット後は、どちらも `rti` だけのルーチンを指しています。予期しない割り込みが来ても、何も起きません。自分のハンドラを使うには、そのアドレスをここに書き込みます。(自作プログラム用のメモリは `$0300-$03F7` になりました。)

## 3. NMI: ボタンを押した回数を数える

`tutorial/nmi_count.s` は、ハンドラを登録して、`jmp loop` で空回りします。NMI のたびにハンドラが実行され、`COUNT`(`$03F0`)に 1 を足して `!` を出力します。

```
start:  lda #<handler           ; NMI ベクタをハンドラに向ける
        sta NMIVEC
        lda #>handler
        sta NMIVEC+1
        lda #$00
        sta COUNT
loop:   jmp loop                ; 主プログラムは何もしない

handler:
        pha                     ; CPU が保存したのは PC と P だけ。A は自分で保存する
        inc COUNT
wait:   lda UART_STATUS
        and #$02                ; 送信可?
        beq wait
        lda #'!'
        sta UART_DATA
        pla
        rti                     ; P と PC を戻す(I フラグも元に戻る)
```

実行します。

```bash
swift run Glow65App --load tutorial/nmi_count.bin@0300
```

POWER を入れて、`G 0300` と入力します。CPU は空回りしているので、端末にプロンプトは出ません。パネルの **NMI** ボタンを押します。押すたびに `!` が1つ出ます。止めるには RESET を押します(RESET は RAM を保持します)。そのあと、回数を確認します。

```
D 03F0 03F0
```

最初の1バイトが、押した回数です。

## 4. パネルで割り込みを観察する

SPEED を 1Hz か 10Hz、STEP MODE を CYCLE にします。または RUN/STOP で CPU を止めて、STEP を使います。プログラムが `$030F` の `jmp loop` で空回りしている間に **NMI** を押し、STEP を進めると、割り込みの受け付けがバスアクセスとして見えます。

| # | アドレス | データ | R/W | 内容 |
|---|---|---|---|---|
| 1 | `$01FD` | `03` | 書き込み | PC の上位バイトを積む |
| 2 | `$01FC` | `0F` | 書き込み | PC の下位バイトを積む |
| 3 | `$01FB` | `26` | 書き込み | P を積む(スタック上では bit5 が常に 1) |
| 4 | `$FFFA` | `C8` | 読み出し | NMI ベクタの下位バイト |
| 5 | `$FFFB` | `F3` | 読み出し | NMI ベクタの上位バイト |

この値は `nmi_count` を実行したときのものです。スタックポインタは `$FD`(モニタの `G` コマンドが、戻りアドレスをすでに積んでいます)、PC は `$030F`(`jmp loop`)でした。5つ目のあと、PC は `$F3C8` です。ここはモニタの `jmp (NMIVEC)` で、次の数ステップで `$03F8/$03F9` を読み、CPU は `$0312` にある自分の `handler` に着きます。最初のアクセスには SYNC が付きません。割り込みの受け付けでは、オペコードをフェッチしないからです。実機の 6502 はここに 7 サイクルかけ、余分なダミーリードが2回あります。Glow65 はこれを再現しないので、アクセスは5つに見えます。

`rti` のあと、P と PC の LED は元の値に戻り、スタックポインタも `$FD` に戻ります。

## 5. IRQ: 割り込みでエコーする

第4章のプログラムは、1文字ごとにループで待っていました。IRQ を使うと、主プログラムは別の仕事をしていて、文字が届いたときに UART が割り込みます。`tutorial/irq_echo.s` は、16 ビットのカウンタ(`$03F0` が下位、`$03F1` が上位)を数え続け、その間にハンドラが打った文字をエコーします。

UART の制御レジスタ(`$A000`)に、新しいビットがあります。

| ビット | 意味 |
|---|---|
| 制御レジスタの bit7 | 1 で、受信した文字が待っている間、IRQ を出す |
| 状態レジスタの bit7 | 1 は、この UART が割り込みを要求している |

準備は次の順に行います。

```
        sei                     ; 準備の間は割り込みを受けない
        ...                     ; IRQVEC($03FA)にハンドラのアドレスを書く
        lda #$80                ; UART 制御の bit7: 文字が届いたら IRQ を出す
        sta UART_STATUS         ; ($A000 は、読むと状態、書くと制御)
        cli                     ; CPU が IRQ を受け付けるようにする
```

ハンドラは、文字を読んでエコーし、Enter を終了の合図として扱います。

```
handler:
        pha
        lda UART_DATA           ; データレジスタを読むと、IRQ の要求が下がる
        cmp #$0D
        beq enter
        pha
wait:   lda UART_STATUS
        and #$02
        beq wait
        pla
        sta UART_DATA           ; エコー
        pla
        rti
enter:  sta DONE                ; A = $0D(0 ではない): 主プログラムに終了を知らせる
        pla
        rti
```

`swift run Glow65App --load tutorial/irq_echo.bin@0300` で起動し、`G 0300` を実行します。打った文字はエコーされます。Enter を押すと、モニタのプロンプトが戻ります。カウンタを見ます。

```
D 03F0 03F2
```

`$03F0/$03F1` は、文字を打っている間に主プログラムが数えた値です。`$03F2` は `0D` で、ハンドラが立てたフラグです。

`lda UART_DATA` の行が重要です。IRQ はレベルで働きます。UART は、未読の文字がある間、線を上げ続けます。`$A001` を読まずに戻るハンドラは、すぐにまた割り込まれ、それが延々と続きます。

## 6. BRK も割り込み

`brk`(オペコード `$00`)は、PC に 2 を足した値と P を積み、I を立て、**IRQ** ベクタ経由でジャンプします。ハードウェアの IRQ と同じ経路なので、`$03FA/$03FB` が両方に使われます。`brk` の次の1バイトは、戻るときに飛ばされます。これは自由に使える「署名」バイトで、ハンドラが読めば、どの `brk` から来たかがわかります。(積まれた P の B フラグで、`brk` から来たのか IRQ から来たのかを区別できます。)

## 7. 試してみよう

1. **SP を見る。** STEP で進めながら NMI を押します。3回積んだあと、SP の LED は `$FD` から `$FA` になり、`rti` のあとで `$FD` に戻ります。
2. **数え方を変える。** `nmi_count.s` で、`!` の代わりに回数を文字で出力します。COUNT に `#'0'` を足して出力します(9回まで)。
3. **読み忘れる。** `irq_echo.s` のハンドラの最初の命令を `rti` にして、`$A001` を読まないようにします。1文字打つと、主プログラムの数え上げが止まり、エコーも出ません。なぜでしょうか。(CPU を遅くして PC を見てください。割り込みの受け付け、ハンドラ、`rti` を、ひたすら繰り返しています。)回復するには RESET を押します。
4. **BRK を使う。** `E 0300 A9 01 00 60 8D F0 03 60` と入力して、`G 0300` を実行します。`$0302` の `brk` は、既定の `rti` ハンドラを通って、`$0303` の `60` を飛ばし、`$0304` から再開します。`D 03F0 03F0` で `01` が見えます。
5. **止める。** `sei` は IRQ を止めますが、NMI は止めません。`nmi_count.s` の `jmp loop` の前に `sei` を入れて、それでも NMI を押してみます。

## 8. 覚えておくこと

- NMI はマスクできません。IRQ は I フラグでマスクされます。
- CPU が保存するのは PC と P だけです。A、X、Y を使うなら、ハンドラで保存します。
- ハンドラは `rts` ではなく `rti` で終わります。
- レベルで働く IRQ は、要因の側で解除します(ここでは `$A001` を読む)。
- モニタのウォームスタートは UART の割り込みを切ります。割り込みを許可したまま `rts` でモニタに戻っても安全です。
