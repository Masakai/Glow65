# チュートリアル 7: 65C02 に切り替える

[English](07-65c02.md) | [日本語](07-65c02.ja.md) &nbsp;·&nbsp; [← 6. 割り込み](06-interrupts.ja.md)

65C02 は 6502 の後継です。6502 のプログラムをそのまま動かせて、プログラムを短くできる命令が加わっています。Glow65 は既定では 6502 として動き、指定すると 65C02 として動きます。この章では、小さなプログラムを CPU ごとに1つずつ、合わせて2通り書いてサイズを比べ、65C02 用のプログラムを両方のマシンで動かして、未定義命令がどう動くかを見ます。以下の内容はすべて Glow65 で実行し、`Tests/Glow65Tests/TutorialChapter65C02Tests.swift` で確認しています。

## 1. 65C02 で加わったもの

この章では、新しい命令のうち4つを使います。

| 命令 | バイト数 | 動作 | 6502 でのやり方 |
|---|---|---|---|
| `stz addr` | 2〜3 | メモリに 0 を書く | 先に `lda #$00`、次に `sta addr` |
| `inc a` | 1 | A に 1 を足す | `clc` と `adc #$01`(3 バイト) |
| `bra label` | 2 | 必ず分岐する | `jmp label`(3 バイト) |
| `phx` / `plx` | 1 | X をスタックに積む/取り出す(Y は `phy` / `ply`) | `txa`、`pha`、`pla`、`tax`(A を経由) |

65C02 には、このほかにも新しいアドレッシングモードと命令(`wai`、`stp`、ビット命令など)があります。詳しくはマニュアルの [4.11 65C02 で加わるモード](../manual/ja/04-addressing.md#411-65c02-で加わるモード)と [5.7 65C02](../manual/ja/05-7-65c02.md) を見てください。Glow65 での実装は[実装仕様書](../documents/specs/2026-10-12-65c02-mode.md)にあります。

## 2. 同じプログラムを2通り

どちらのプログラムも、2つのことをします。`$03D0-$03DF` の16バイトを 0 で埋め、そのあと16ビットの値を 0 から `$0300` まで数えて `COUNT`(`$03F0` が下位、`$03F1` が上位)に書きます。数えるときは、上位バイトを A に、下位バイトをメモリに持ちます。

[`clear_6502.s`](clear_6502.s) が 6502 用です。

```
        ldx #$0F        ; X = 15: index of the last byte of the area
        lda #$00        ; a 6502 cannot store a constant: A must hold the 0
clr:    sta BUF,x       ; clear one byte
        dex
        bpl clr         ; repeat until X wraps from 0 to $FF
        sta COUNT       ; A is still 0
loop:   cmp #$03        ; A = high byte of the count: finished?
        beq done
        inc COUNT       ; low byte + 1
        bne loop        ; no wrap: next
        clc             ; the low byte wrapped: high byte + 1
        adc #$01
        jmp loop        ; the 6502 has no unconditional short branch
done:   sta COUNT+1
        rts
```

[`clear_65c02.s`](clear_65c02.s) が 65C02 用です。

```
        ldx #$0F        ; X = 15: index of the last byte of the area
clr:    stz BUF,x       ; STZ stores a zero without using A
        dex
        bpl clr         ; repeat until X wraps from 0 to $FF
        stz COUNT       ; the low byte of the count
        lda #$00        ; A = high byte of the count
loop:   cmp #$03        ; finished?
        beq done
        inc COUNT       ; low byte + 1
        bne loop        ; no wrap: next
        inc a           ; the low byte wrapped: INC A adds 1 to A
        bra loop        ; BRA: unconditional branch, 2 bytes
done:   sta COUNT+1
        rts
```

65C02 版は、A に 0 を読み込む代わりに `stz`、`clc` と `adc #$01` の代わりに `inc a`、`jmp` の代わりに `bra` を使っています。途中のループの形は同じです。

## 3. アセンブルする

これまでの章と同じく、`Tools/assemble.sh` には `cc65` パッケージが必要です。65C02 のソースは `.setcpu "65C02"` で始まります。これで `ca65` が新しい命令を受け付けます。書かないと `stz` はエラーになります。6502 のソースには `.setcpu "6502"` と書いてあります。

```bash
Tools/assemble.sh tutorial/clear_6502.s
Tools/assemble.sh tutorial/clear_65c02.s
```

```
tutorial/clear_6502.bin: 32 bytes (load at $0300)
tutorial/clear_65c02.bin: 29 bytes (load at $0300)
```

65C02 版は3バイト短くなります。`inc a` で2バイト、`bra` で1バイトです。このプログラムでは `stz` は短くなる要因になっていません。65C02 版も上位バイトのために `lda #$00` が必要で、6502 版は1回の `lda #$00` で両方をまかなえるからです。`.bin` は `tutorial/` にコミットしてあるので、この手順は飛ばせます。

## 4. 65C02 で動かす

Glow65 を 65C02 として起動し、65C02 用のバイナリを読み込みます。`--cpu 65c02` は、どちらのプログラムにも使えます。

```bash
swift run glow65-cli --cpu 65c02 --load tutorial/clear_65c02.bin@0300
```

または

```bash
swift run Glow65App --cpu 65c02 --load tutorial/clear_65c02.bin@0300
```

アプリでは、POWER を上げて、ターミナルをクリックします。消えていく様子が分かるように、最初に領域を `$AA` で埋めます。

```
E 03D0 AA AA AA AA AA AA AA AA AA AA AA AA AA AA AA AA
```

プログラムを一覧します。モニタの `L` コマンドは実行時に CPU の種類を判定するので、65C02 では新しい命令を名前で表示します。

```
L 0300 031C
```

```
0300  A2 0F     LDX   #$0F
0302  9E D0 03  STZ   $03D0,X
0305  CA        DEX
0306  10 FA     BPL   $0302
0308  9C F0 03  STZ   $03F0
030B  A9 00     LDA   #$00
030D  C9 03     CMP   #$03
030F  F0 08     BEQ   $0319
0311  EE F0 03  INC   $03F0
0314  D0 F7     BNE   $030D
0316  1A        INC   A
0317  80 F4     BRA   $030D
0319  8D F1 03  STA   $03F1
031C  60        RTS
```

実行して、領域とカウンタをダンプします。

```
G 0300
D 03D0 03F1
```

```
03D0: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
03E0: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
03F0: 00 03 00 00 00 00 00 00 24 F4 24 F4 00 00 00 00
```

`$03D0` からの16バイトは 0 に戻り、`$03F0/$03F1` は `00 03` です。下位バイトが先なので、`$0300` を表します。`$03F8-$03FB` は、第6章の割り込みベクタです。

## 5. 6502 で動かす

次に、同じバイナリを既定の CPU で起動します。`--cpu` は付けません(`--cpu 6502` と書いても同じです)。

```bash
swift run glow65-cli --load tutorial/clear_65c02.bin@0300
```

もう一度、領域を `$AA` で埋めて、プログラムを一覧します。

```
E 03D0 AA AA AA AA AA AA AA AA AA AA AA AA AA AA AA AA
L 0300 0318
```

```
0300  A2 0F     LDX   #$0F
0302  9E        .BYTE $9E
0303  D0 03     BNE   $0308
0305  CA        DEX
0306  10 FA     BPL   $0302
0308  9C        .BYTE $9C
0309  F0 03     BEQ   $030E
030B  A9 00     LDA   #$00
030D  C9 03     CMP   #$03
030F  F0 08     BEQ   $0319
0311  EE F0 03  INC   $03F0
0314  D0 F7     BNE   $030D
0316  1A        .BYTE $1A
0317  80        .BYTE $80
0318  F4        .BYTE $F4
```

バイトは同じですが、6502 は `$9E`、`$9C`、`$1A`、`$80` を知らないので、`L` は `.BYTE` と表示します。Glow65 の 6502 は、このような未定義のオペコードを1バイトの NOP(2サイクル)として実行します。そのあとに続くバイト(`stz` や `bra` のオペランドだったもの)は、それぞれ独立した命令として読まれます。`D0 03` は `BNE`、`F0 03` は `BEQ` になります。実行します。

```
G 0300
D 03D0 03F1
```

```
03D0: AA AA AA AA AA AA AA AA AA AA AA AA AA AA AA AA
03E0: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
03F0: 00 00 00 00 00 00 00 00 24 F4 24 F4 00 00 00 00
```

何も消えておらず、領域は `$AA` のままです。カウンタは `00 03` ではなく `00 00` です。ここでは `inc a` が NOP なので、A は 3 になりません。下位バイトが256通りを1周すると、A が 0 のままループを抜けます。プログラムはクラッシュせず、エラーも出さず、最後まで実行して、間違った答えでモニタに戻りました。CPU は警告してくれません。65C02 用のプログラムを 6502 のマシンに読み込むと、こうなります。

逆の向きは問題ありません。6502 用のプログラムは 65C02 にもある命令だけを使っているので、`clear_6502.bin` は、どちらのマシンでも同じダンプになります。

```
03D0: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
03E0: 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
03F0: 00 03 00 00 00 00 00 00 24 F4 24 F4 00 00 00 00
```

参考までに、`clear_6502.bin` に対する `L 0300 031F` は 6502 の命令だけを表示し、どちらの CPU でも同じ行を出力します。

```
0300  A2 0F     LDX   #$0F
0302  A9 00     LDA   #$00
0304  9D D0 03  STA   $03D0,X
0307  CA        DEX
0308  10 FA     BPL   $0304
030A  8D F0 03  STA   $03F0
030D  C9 03     CMP   #$03
030F  F0 0B     BEQ   $031C
0311  EE F0 03  INC   $03F0
0314  D0 F7     BNE   $030D
0316  18        CLC
0317  69 01     ADC   #$01
0319  4C 0D 03  JMP   $030D
031C  8D F1 03  STA   $03F1
031F  60        RTS
```

## 6. パネルの CPU スイッチ

アプリでは、パネルの **CPU** スイッチで 6502 と 65C02 を切り替えます。操作できるのは POWER が OFF のときだけで、起動時の CPU は `--cpu` オプションで選びます。CPU を変えるには、POWER を OFF にしてスイッチを動かし、もう一度 POWER を ON にします。電源を入れると RAM が消えるので、プログラムは POWER を ON にしたあとで読み込みます。`--load` は毎回そうしてくれます。**File → Load Program…** を使うか、バイトを入力しても構いません。

## 7. 試してみよう

1. **上限を変える。** 65C02 のマシンで `E 030E 01` と入力して `cmp` のオペランドを変え、もう一度 `G 0300` を実行します。カウンタは `$0100` で止まります。`D 03F0 03F1` が出力する行は、`00 01` で始まります。
2. **X を積む。** `E 0300 A2 07 DA A2 00 FA 8E F0 03 60` と入力します。プログラムは `ldx #$07`、`phx`、`ldx #$00`、`plx`、`stx $03F0`、`rts` です。`G 0300` で実行して、`D 03F0 03F0` を見ます。65C02 では先頭のバイトが `07` です。`plx` が 7 を戻してくれました。6502 では `00` です。`phx` と `plx` が何もしないからです。
3. **自分で書く。** `dec a` と `bra` を使って、A で 10 から数え下ろし、最後に `stz` で 0 を書きます。

## 8. 覚えておくこと

- 65C02 は 6502 のプログラムをすべて実行でき、`stz`、`inc a`、`bra`、`phx`、`plx` などの命令が加わっています。
- どちらの CPU 向けかは、`.setcpu "6502"` か `.setcpu "65C02"` で `ca65` に伝えます。
- 6502 では、新しいオペコードは未定義です。Glow65 はそれを NOP として実行するので、65C02 用のプログラムはエラーなしで間違った結果を出します。
- `L` が `STZ`、`BRA` などの新しい命令を名前で表示するのは、65C02 のマシンだけです。6502 では `.BYTE` と表示します。
- CPU を変えられるのは、POWER が OFF のときだけです。
