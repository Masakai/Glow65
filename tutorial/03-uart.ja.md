# チュートリアル 3: UART と話す

[English](03-uart.md) | [日本語](03-uart.ja.md) &nbsp;·&nbsp; [← 2. 足し算](02-addition.ja.md) &nbsp;·&nbsp; [4. キーボードを読む →](04-echo.ja.md)

ここまでのプログラムは、メモリを書き換えるだけでした。この章では、UART に直接書き込んで、端末に文字を出します。以下の内容はすべて Glow65 で実行し、`Tests/Glow65Tests/TutorialChapterTests.swift` で確認しています。

## 1. UART は 2 つのアドレス

バスのアドレスは、いつも RAM につながっているわけではありません。Glow65 にはシリアルポート(UART。MC6850 を参考にしたもの)があり、2つのアドレスにあります。そこを読み書きすると、RAM ではなく、デバイスと話すことになります。

| アドレス | 読む | 書く |
|---|---|---|
| `$A000` | 状態: bit0 = 受信した文字がある、**bit1 = 送信できる** | 制御 |
| `$A001` | 受信した文字 | **この文字を送る** |

アプリの端末は、そのポートの向こう側にあります。文字を出すには、状態の bit1 が立つまで待ってから、`$A001` に書きます。(Glow65 の UART は、いつでも送れる状態なので、待ちはすぐ終わります。実際の UART はビットをゆっくり送るので、待つことに意味があります。ここでも、待ちは書いておきます。)

## 2. プログラム

[`hello.s`](hello.s) は「HELLO, GLOW65」と改行を送ります。

```
        ldx #$00            ; X = メッセージの添字
next:   lda message,x       ; 次の文字を取り出す
        beq done            ; 0 のバイトはメッセージの終わり
        tay                 ; UART を調べる間、文字を Y に預けておく
wait:   lda UART_STATUS
        and #$02            ; 送信レジスタは空いているか
        beq wait            ; まだなら、もう一度見る
        tya                 ; 空いた: 文字を A に戻す
        sta UART_DATA       ; 送る
        inx
        jmp next
done:   rts
message:
        .byte "HELLO, GLOW65", $0D, $0A, $00
```

- `lda message,x` は、`message + X` のバイトを読みます。X を増やしていくと、文章を順に辿れます。
- 状態を A に読み込むと、文字が消えてしまいます。そこで `tay` で文字を Y に預け、`tya` で戻しています。
- `and #$02` で bit1 だけを残します。結果が 0 なら、UART はまだ準備できていないので、`beq wait` でやり直します。
- `$0D, $0A` は復帰と改行で、次のプロンプトが新しい行から始まります。最後の `$00` がメッセージの終わりです。

## 3. 読み込んで実行する

`hello.bin` を読み込む(`swift run Glow65App --load tutorial/hello.bin@0300`、または **File → Load Program…**)か、コードとメッセージを別々に入力します(合わせて 40 バイト)。

```
E 0300 A2 00 BD 18 03 F0 10 A8 AD 00 A0 29 02 F0 F9 98 8D 01 A0 E8 4C 02 03 60
E 0318 48 45 4C 4C 4F 2C 20 47 4C 4F 57 36 35 0D 0A 00
L 0300 0317
```

`L` は次のように表示します。

```
0300  A2 00     LDX   #$00
0302  BD 18 03  LDA   $0318,X
0305  F0 10     BEQ   $0317
0307  A8        TAY
0308  AD 00 A0  LDA   $A000
030B  29 02     AND   #$02
030D  F0 F9     BEQ   $0308
030F  98        TYA
0310  8D 01 A0  STA   $A001
0313  E8        INX
0314  4C 02 03  JMP   $0302
0317  60        RTS
```

メッセージは `$0318` から始まります。`$0317` より先まで表示すると、文字が意味のない命令(`PHA` など)として出ます。`L` はコードとデータを区別できません。

実行します。

```
G 0300
```

```
HELLO, GLOW65
*
```

文字はあなたのプログラムが出したもので、`rts` でモニタに戻ります。

## 4. パネルで見る

全速でも、文字ごとに **WRITE** と **TX** の LED が光るのが見えます。1文字を詳しく見るには、プログラムをループにします(`E 0317 4C 00 03` で `rts` を `jmp $0300` に替える)。`G 0300` で実行し、そのあと **SPEED** を **10 Hz**、**RUN/STOP** を STOP にします。遅くする前に、ループがメッセージを何度も出すので、端末は最初、行でいっぱいになります。先に **G SPEED** を **10 Hz** にしておくと、`G 0300` を実行した時点から 10 Hz で動くので、行でいっぱいになりません。RESET でモニタに戻ると、SPEED は元の速度に戻ります。次に **STEP MODE** を CYCLE にし、INSTRUCTION AT PC が `STA $A001` のときに **WRITE** の LED が点灯するところまで、**STEP** を押します。

ループは、適当な場所で止めたので、最初に見える文字は、メッセージのどの文字かわかりません。WRITE が点灯するまで STEP を押し続け、次の行を読んでください。

| LED の行 | プログラムが文字を書き込むときに見えるもの |
|---|---|
| ADDRESS BUS | いつも `$A001`: **A15**、**A13**、**A0** が点灯 |
| DATA BUS | その文字の ASCII コード。`H` は `$48`(**D6** と **D3** が点灯)、続く `E`、`L`、`L`、`O` は `$45`、`$4C`、`$4C`、`$4F` |
| WRITE | 点灯 |

書き込みの前には、必ず `$A000` の読み出しがあります。UART に「送れますか」と聞いているところです。

## 5. 近道: モニタのルーチンを使う

文字を待って送るルーチンは、モニタにあります。`$F003` の `CHROUT` です(アドレスは固定なので、自作プログラムから呼べます)。[`hello_monitor.s`](hello_monitor.s) は、hello.s から待ちのループを除いたものです。

```
        ldx #$00
next:   lda message,x
        beq done
        jsr $F003           ; モニタが待って、A を送る
        inx
        jmp next
done:   rts
```

31 バイトです。入力するなら、メッセージを `$030F` に置きます。

```
E 0300 A2 00 BD 0F 03 F0 07 20 03 F0 E8 4C 02 03 60
E 030F 48 45 4C 4C 4F 2C 20 47 4C 4F 57 36 35 0D 0A 00
G 0300
```

同じ文字が出ます。BASIC の出力も、この `CHROUT` を通っています。

## 6. 試してみる

1. **自分のメッセージ。** RESET を押し、`E 0318 47 4F 4F 44 0D 0A 00`(GOOD、改行、終わりの印)を入力して、`G 0300` を実行します。`0D 0A` を省くと、次のプロンプトが文字のすぐ後ろに出ます。メッセージは短くしてください。`$03F0` にぶつかってはいけません。
2. **別の ASCII コード。** `E 0318 41 42 43 0D 0A 00` は `ABC` を出します。文字は1つずつコードが増えるので、各バイトに 3 を足せば `DEF` になります。
3. **受信。** 状態の bit0 は文字が届いたことを示し、`$A001` を読むとその文字が返ります。bit0 を待ち、文字を読み、そのまま送り返すプログラムがエコーです。同じ部品で、書いてみてください。
