# チュートリアル 2: 足し算とキャリーフラグ

[English](02-addition.md) | [日本語](02-addition.ja.md) &nbsp;·&nbsp; [← 1. LED カウンタ](README.ja.md) &nbsp;·&nbsp; [3. UART →](03-uart.ja.md)

6502 は、1回に 8 ビットずつ足し算をします。255 より大きい数を足すには、下位バイトを足し、次に上位バイトを足して、その間で**キャリー**(繰り上がり)を受け渡します。この章では 16 ビットの足し算を書き、キャリーフラグが下位と上位の間を移る様子を観察します。以下の内容はすべて Glow65 で実行し、`Tests/Glow65Tests/TutorialChapterTests.swift` で確認しています。

## 1. プログラム

[`add.s`](add.s) は `SUM = A + B` を計算します。数は2バイトで、**下位バイトが先**です。

| 数 | 下位バイト | 上位バイト |
|---|---|---|
| A | `$03F0` | `$03F1` |
| B | `$03F2` | `$03F3` |
| SUM | `$03F4` | `$03F5` |

```
        clc             ; 下位バイトには、繰り上がりを入れない
        lda A_LO        ; まず下位バイト
        adc B_LO        ; A = A_LO + B_LO
        sta SUM_LO
        lda A_HI        ; 次に上位バイト
        adc B_HI        ; A = A_HI + B_HI + 下位バイトからの繰り上がり
        sta SUM_HI
        rts             ; モニタに戻る
```

`adc` は「キャリー付きの足し算」で、メモリのバイトと**キャリーフラグ**の両方を足します。`clc` で先にキャリーを消すので、下位バイトの足し算は繰り上がりなしで始まります。下位バイトの足し算が 255 を超えると、CPU がキャリーフラグを立て、2回目の `adc` がそれを上位バイトに足します。

プログラムは `rts` で終わります。モニタの `G` はプログラムをサブルーチンとして呼ぶので、`rts` で `*` のプロンプトに戻ります。

## 2. 読み込む

第1章と同じ方法で `add.bin` を読み込む(`swift run Glow65App --load tutorial/add.bin@0300`、または **File → Load Program…**)か、20 バイトを入力します。

```
E 0300 18 AD F0 03 6D F2 03 8D F4 03 AD F1 03 6D F3 03 8D F5 03 60
L 0300 0313
```

`L` は次のように表示します。

```
0300  18        CLC
0301  AD F0 03  LDA   $03F0
0304  6D F2 03  ADC   $03F2
0307  8D F4 03  STA   $03F4
030A  AD F1 03  LDA   $03F1
030D  6D F3 03  ADC   $03F3
0310  8D F5 03  STA   $03F5
0313  60        RTS
```

`$0313` より先まで表示すると、`BRK` の行が出ます。何も置いていないメモリのゼロが、そう見えているだけです。`L` はコードとデータを区別できません。

## 3. 実行する

A と B に数を入れ、プログラムを実行して、結果を見ます。

```
E 03F0 05 00 07 00
G 0300
D 03F0 03F5
```

A は `$0005`、B は `$0007` です。ダンプの先頭6バイトは `05 00 07 00 0C 00` で、SUM は `$000C`(12)です。`*` のプロンプトは自動的に戻ります。

次は、キャリーが必要な足し算です。`$01FF + $0001` を計算します。

```
E 03F0 FF 01 01 00
G 0300
D 03F0 03F5
```

先頭6バイトは `FF 01 01 00 00 02` で、SUM は `$0200` です。下位バイトの `$FF + $01` は1バイトに収まらないので、和の下位バイトは `$00` になり、繰り上がりが次に渡されます。上位バイトの足し算は `$01 + $00 + 1 = $02` になります。

## 4. キャリーを観察する

プログラムは数マイクロ秒で終わります。観察するために、最後の `rts` を `jmp $0300` に替えて、ループにします。

```
E 03F0 FF 01 01 00
E 0313 4C 00 03
G 0300
```

プログラムは繰り返し続けるので、プロンプトは戻りません。そのあと、次のようにします。

1. **SPEED** を **10 Hz** にし、**RUN/STOP** を STOP にします。
2. **STEP MODE** を INSTR にして、**INSTRUCTION AT PC** が `0300  18  CLC` になるまで、**STEP** を押します。(CPU はループの途中で止まっているので、最大8回押すことになります。)
3. そのまま STEP を押し続けます。押すごとに、**A** の LED と、STATUS P の行の **C** フラグ(いちばん右の LED)を見ます。

| 回 | 押す前の PC の命令 | 押したあとの A | 押したあとの C | 起きたこと |
|---|---|---|---|---|
| 1 | `0300  CLC` | 変わらない | 0 | キャリーが消える |
| 2 | `0301  LDA $03F0` | `$FF` | 0 | A = A の下位バイト |
| 3 | `0304  ADC $03F2` | `$00` | **1** | `$FF + $01 = $100`。下位 8 ビットは 0、キャリーは 1。Z フラグも点灯する |
| 4 | `0307  STA $03F4` | `$00` | 1 | 和の下位バイトを保存 |
| 5 | `030A  LDA $03F1` | `$01` | 1 | A = A の上位バイト。`lda` は C を変えない |
| 6 | `030D  ADC $03F3` | `$02` | 0 | `$01 + $00 +` キャリー(1)`= $02`。新しい繰り上がりはなし |
| 7 | `0310  STA $03F5` | `$02` | 0 | 和の上位バイトを保存 |
| 8 | `0313  JMP $0300` | `$02` | 0 | 先頭に戻る |

キャリーは3回目に点灯し、6回目で使い切られます。複数バイトの計算は、この仕組みで成り立っています。

## 5. 試してみる

先に RESET を押し、`E 0313 60` で `rts` を元に戻します(ループ版はモニタに戻りません)。`$03F0-$03F5` の数は残っています。

1. **あふれ。** `E 03F0 FF FF 01 00` のあと `G 0300`、`D 03F0 03F5`。SUM は `$0000` になります。上位バイトから出た繰り上がりはどこにも保存されないので、16 ビットの和は一周して戻ります。
2. **引き算。** 引き算も同じやり方で、キャリーフラグは「借りなし」を表します。最初の `sbc` の前に `sec` を置きます。`E 0300 38`(`sec`)、`E 0304 ED F2 03`(`sbc $03F2`)、`E 030D ED F3 03`(`sbc $03F3`)でオペコードを替えます。A = `$0200`、B = `$0001`(`E 03F0 00 02 01 00`)なら、SUM は `$01FF` になります。
3. **24 ビットにする。** 各数に3バイト目を足し、プログラムに `lda` / `adc` / `sta` を1組足します。順番は同じです。下位バイトが先で、キャリーを渡していきます。
