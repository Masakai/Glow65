# チュートリアル 4: キーボードを読む、エコーのプログラム

[English](04-echo.md) | [日本語](04-echo.ja.md) &nbsp;·&nbsp; [← 3. UART](03-uart.ja.md) &nbsp;·&nbsp; [5. USR →](05-usr.ja.md)

第3章では、UART から文字を送り出しました。この章では、UART から文字を読み込みます。プログラムはキーを待ち、読み取って、そのまま送り返します。打った文字が、画面に出るようになります。以下の内容はすべて Glow65 で実行し、`Tests/Glow65Tests/TutorialChapterTests.swift` で確認しています。

## 1. 画面にエコーが必要な理由

アプリの端末は、キーを打っても、自分では表示しません。キーは UART に届き、端末が表示するのは、UART から送り出された文字だけです。モニタで文字を打つと見えるのは、**モニタ**が、キーを1つずつ読んで、送り返しているからです。

打った文字を画面に出したいプログラムは、同じことをする必要があります。読んで、送り返す。これがエコーです。

受信は、送信と同じ2つのレジスタを使います。

| アドレス | 読む | 書く |
|---|---|---|
| `$A000` | 状態: **bit0 = 受信した文字がある**、bit1 = 送信できる | 制御 |
| `$A001` | **受信した文字**(読むと、UART から取り除かれる) | 文字を送る |

プログラムには、キーがいつ押されるかがわかりません。そこで**ポーリング**をします。bit0 が立つまで、状態を何度も読み直します。

## 2. プログラム

[`echo.s`](echo.s):

```
loop:   lda UART_STATUS
        and #$01            ; 文字が届いたか
        beq loop            ; まだ: もう一度見る
        lda UART_DATA       ; 届いた: 読む
        cmp #$0D            ; Enter か
        beq done            ; そうなら終わる
        tay                 ; 文字を Y に預ける
send:   lda UART_STATUS
        and #$02            ; 送信できるか
        beq send            ; まだ: もう一度見る
        tya
        sta UART_DATA       ; 送り返す
        jmp loop
done:   lda #$0D            ; 改行を送る
        jsr CHROUT
        lda #$0A
        jsr CHROUT
        rts
```

- 最初の3行が、待ちのループです。`and #$01` は状態の bit0 だけを残します。0 の間は、`beq loop` で、また最初に戻ります。
- `cmp #$0D` は、A と Enter のコードを比べます。等しければ Z フラグが立ち、`beq done` が飛びます。この出口がないと、プログラムはモニタに戻りません。
- 真ん中は、第3章の送信のコードです。
- 最後は、モニタの `CHROUT`(`$F003`)で、復帰と改行を送ります。次のプロンプトが、新しい行から始まります。

## 3. 読み込んで実行する

`echo.bin` を読み込む(`swift run Glow65App --load tutorial/echo.bin@0300`、または **File → Load Program…**)か、40 バイトを入力します。

```
E 0300 AD 00 A0 29 01 F0 F9 AD 01 A0 C9 0D F0 0F A8 AD 00 A0 29 02 F0 F9 98 8D 01 A0 4C 00 03 A9 0D 20 03 F0 A9 0A 20 03 F0 60
L 0300 0327
```

`L` は次のように表示します。

```
0300  AD 00 A0  LDA   $A000
0303  29 01     AND   #$01
0305  F0 F9     BEQ   $0300
0307  AD 01 A0  LDA   $A001
030A  C9 0D     CMP   #$0D
030C  F0 0F     BEQ   $031D
030E  A8        TAY
030F  AD 00 A0  LDA   $A000
0312  29 02     AND   #$02
0314  F0 F9     BEQ   $030F
0316  98        TYA
0317  8D 01 A0  STA   $A001
031A  4C 00 03  JMP   $0300
031D  A9 0D     LDA   #$0D
031F  20 03 F0  JSR   $F003
0322  A9 0A     LDA   #$0A
0324  20 03 F0  JSR   $F003
0327  60        RTS
```

実行して、文字を打ちます。

```
G 0300
hello
```

打った文字は、モニタではなく、あなたのプログラムが送り返しています。**Enter** を押すと、プログラムが改行を送って戻り、`*` のプロンプトが帰ってきます。

```
hello
*
```

## 4. パネルで見る

1. `G 0300` を、全速で実行します。プログラムはキーを待っているので、プロンプトは戻りません。
2. **SPEED** を **10 Hz** にして、端末で1文字打ちます。まだ何も表示されません。CPU が遅くて、UART を見に行っていないためです。文字は、UART の中で待っています。
3. **INSTRUCTION AT PC** を見ます。`LDA $A000`、`AND #$01`、`BEQ $0300` を繰り返しています。ポーリングのループです。`$A000` を読むたびに、アドレスバスは `$A000`(**A15** と **A13** が点灯)になり、**READ** が点灯します。
4. 次にループを回ったとき、状態の bit0 が立っているので、`beq` は飛びません。プログラムが `$A001` を読みます。アドレスバスは `$A001`(**A15**、**A13**、**A0**)、データバスは、その文字の ASCII コード(`h` は `$68` で、**D6**、**D5**、**D3**)になり、**RX** の LED が点灯します。
5. 数命令あと、プログラムが同じコードを `$A001` に書きます。今度は **WRITE** と **TX** が点灯し、端末に文字が出ます。

Enter を押す前に、**SPEED** を 1 MHz に戻してください。モニタも、また速くなります。

## 5. 試してみる

先に RESET を押します。RAM に読み込んだプログラムは、残っています。

1. **別のキーで終わる。** `E 030B 2E` で、`cmp #$0D` が `cmp #$2E` に変わり、Enter の代わりに `.`(ASCII の `$2E`)で終わります。このとき Enter は、ほかのキーと同じようにエコーされ、行の先頭に戻るだけで、改行はされません。
2. **大文字にする。** [`echo_upper.s`](echo_upper.s)(50 バイト、`echo_upper.bin`)は、`a`〜`z` を `A`〜`Z` にして返します。キーを読んでから送るまでの間に、次を足しています。

   ```
   cmp #$61            ; 'a'
   bcc send_it         ; 'a' より小さい: そのまま
   cmp #$7B            ; 'z' の次
   bcs send_it         ; 'z' 以上: そのまま
   and #$DF            ; bit5 を消す
   ```

   ASCII では、`a`〜`z` が `$61`〜`$7A`、`A`〜`Z` が `$41`〜`$5A` です。違いは bit5(`$20`)だけなので、`and #$DF` で、小文字が大文字になります。`cmp` は、A がオペランド以上のときにキャリーフラグを立てます。`bcc` と `bcs` は、それを調べています。`echo_upper.bin` を読み込んで実行し、`Hello, World 123` と打ってみてください。
3. **打ったキーの数を数える。** 空いているメモリ(例: `$03F0`)に数を置き、文字を読むたびに 1 を足します。Enter を押したあと、`D 03F0 03FF` で数を見ます。
